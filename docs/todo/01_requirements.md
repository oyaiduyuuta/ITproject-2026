# TODOアプリ V1 要件定義書 (01_requirements.md)

## 1. 目的・対象範囲
- **目的**: 既存のExpress + TypeScript + EJSサイトにNeon PostgreSQLと接続するTODO管理機能を追加し、ローカル・Vercel Preview・Production環境で動作確認を行う[cite: 27, 29]。
- **対象環境**:
  - バックエンド: Express, TypeScript[cite: 27, 29]
  - フロントエンド: EJS (画面URL: `/todo`)[cite: 27, 29]
  - データベース: Neon PostgreSQL (`DATABASE_URL` を利用)[cite: 27, 29]
  - ホスティング: Vercel (PreviewおよびProductionで同じNeon DBを参照)[cite: 27, 29]
- **前提事項**:
  - 既存の `/` および `/api/db-check` のルートは維持する[cite: 27, 29]。
  - V1では認証機能、優先度、絞り込み、タイトルの編集機能は対象外とする[cite: 29]。
  - 個人情報は扱わず、授業用の架空データのみを使用する[cite: 29]。
- **ファイル配置**: 確定していない実際のファイル配置については「要確認」とし、設計書で決定する[cite: 29]。

## 2. 機能と受け入れ条件

### REQ-01: TODO一覧取得
- **操作**: 画面表示時およびデータ更新後に、自動でAPIを呼び出してTODO一覧を取得・表示する[cite: 29]。
- **入力**: なし (GET `/api/v1/todos`)[cite: 29]
- **結果**: 200 OK と共に TODO オブジェクトの配列を返却する (`{ "status": "success", "data": [...] }`)[cite: 29, 32]
- **エラー**: 500/503 (DB接続障害等)[cite: 29, 33]
- **受け入れ条件**: データが0件の場合、GETは200 OKで `data: []` を返し、画面に「TODOがありません」等の旨を表示できること[cite: 29, 31]。
- **確認方法**: ローカルおよび各確認環境で `/todo` にアクセスし、表示結果および開発者ツールのレスポンスを確認する。

### REQ-02: TODO登録
- **操作**: 入力フォームにタイトルを入力し、登録ボタンを押下する[cite: 29]。
- **入力**: JSON形式 `{ "title": "文字列" }` (POST `/api/v1/todos`)[cite: 29, 32]
- **結果**: 201 Created と共に作成された TODO オブジェクトを返却する (`{ "status": "success", "data": { ... } }`)[cite: 29, 32, 34]
- **エラー**:
  - 400 Bad Request: JSON形式不正、`title` 欠落[cite: 29, 33]
  - 422 Unprocessable Entity: `title` が前後の空白を除いて0文字（空文字）、または101文字以上[cite: 29, 33]
  - 500/503: サーバー・DB障害[cite: 29, 33]
- **受け入れ条件**: 前後空白を除いた `title` が1〜100文字の場合に正常登録され、初期状態 `isCompleted: false` で一覧に追加されること[cite: 29, 32]。
- **確認方法**: 画面からの登録操作および Console/curl でのPOST送信テストを行い、レスポンスと画面更新を確認する[cite: 29, 35, 36]。

### REQ-03: 完了状態の部分更新
- **操作**: 一覧上のチェックボックス等の操作で完了/未完了の状態を変更する[cite: 29]。
- **入力**: パスパラメータ `id` (1以上の整数) および JSON `{ "isCompleted": boolean }` (PATCH `/api/v1/todos/:id`)[cite: 29, 32]
- **結果**: 200 OK と共に更新後の TODO オブジェクトを返却する (`{ "status": "success", "data": { ... } }`)[cite: 29, 32, 34]
- **エラー**:
  - 400 Bad Request: ID型不正、JSON/型不正[cite: 29, 33]
  - 404 Not Found: 指定されたIDが存在しない[cite: 29, 33]
  - 500/503: サーバー・DB障害[cite: 29, 33]
- **受け入れ条件**: 存在するIDに対して `isCompleted` の状態変更が正常に反映され、レスポンスに更新後の状態が含まれること[cite: 29, 32]。
- **確認方法**: 状態変更操作を行い、画面表示の切り替わりおよびデータベース/APIレスポンスの値を確認する[cite: 29, 35, 36]。

### REQ-04: TODO削除
- **操作**: 一覧上の削除ボタンを押下する[cite: 29]。
- **入力**: パスパラメータ `id` (1以上の整数) (DELETE `/api/v1/todos/:id`)[cite: 29]
- **結果**: 204 No Content (レスポンス本文なし)[cite: 29, 32]
- **エラー**:
  - 400 Bad Request: ID型不正[cite: 29, 33]
  - 404 Not Found: 指定されたIDが存在しない[cite: 29, 33]
  - 500/503: サーバー・DB障害[cite: 29, 33]
- **受け入れ条件**: 存在するIDの削除実行時、204が返り、レスポンス本文を解析せずに画面一覧から対象のTODOが消えること[cite: 29, 32, 33]。
- **確認方法**: 削除操作を実行し、ステータスコード204と画面からの削除を確認する[cite: 29, 35, 36]。

## 3. 共通のデータ・エラー条件

### データ仕様
- **ID**: 1以上の整数 (`id`)[cite: 29]
- **Title**: 前後の空白を除き 1〜100 文字の文字列 (`title`)[cite: 29, 32]
- **完了状態**: 真偽値 (`isCompleted`, 初期値 `false`)[cite: 32]
- **作成日時**: ISO 8601形式の文字列 (`createdAt`)[cite: 32]
- **レスポンス形式**: JSONプロパティは camelCase[cite: 31]。成功時は `{ "status": "success", "data": ... }`[cite: 32]

### 共通エラーレスポンス形式
エラーが発生した場合は、以下の統一JSON形式で返却する。
```json
{
  "status": "error",
  "code": "エラーコード",
  "message": "ユーザー向けメッセージ",
  "details": []
}

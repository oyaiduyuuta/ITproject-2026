## 1. ドキュメント概要

* **目的**: 追加要望書（`01_request.md`）に基づき、Express / TypeScript 製既存アプリケーションへ追加する「AI質問機能」の機能要件・非機能要件・画面・制約事項を確定する。
* **対象システム**: 既存 Web アプリケーション（Express / TypeScript / EJS）

## 3. 機能要件

### 3.1. 画面表示機能（GET `/ai`）

* 専用ページとして `/ai` にアクセスした際、AI質問画面（`views/ai/index.ejs`）をレンダリングして返却する。
* 画面には以下の要素を配置する。
* **ページタイトル・説明文**: 機能の用途が分かる見出し
* **質問入力フォーム**: テキストエリアおよび「質問する（送信）」ボタン
* **ステータス表示領域**: 通信中のローディング表示（スピナーまたは「回答を生成中...」のメッセージ）
* **回答表示領域**: AIからの回答テキストを表示するエリア
* **エラー表示領域**: バリデーションエラーや通信エラーを表示するアラートエリア
* **ナビゲーションリンク**: 既存の TOP 画面や TODO 画面へ戻るリンク



### 3.2. 質問送信・AI応答取得機能（POST `/ai/ask`）

* フロントエンド（`public/ai/ai.js`）から非同期通信（`fetch` API / JSON形式）で質問テキストを送信する。
* バックエンド（`aiController` / `aiService`）は以下の処理を行う。
1. リクエストボディの入力値検証（バリデーション）を実施する。
2. `@google/genai` SDK を経由して Gemini API（`gemini-3.8-flash`）に質問テキストを送信する。
3. 取得した回答テキストを JSON 形式でフロントエンドに返却する。


* フロントエンドはレスポンスを受け取り、ローディング表示を解除して回答表示領域に結果を描画する。
* 通信中（リクエスト送信〜レスポンス受信完了まで）は送信ボタンを非活性（`disabled`）とし、二重送信を防止する。

### 3.3. 入力値制約（バリデーション要件）

フロントエンドおよびバックエンド双方で以下の制約を設ける。

| 項目 | 制約ルール | エラー時の挙動 |
| --- | --- | --- |
| **必須チェック** | 空文字および空白文字（スペース・改行のみ）は不可 | HTTP `400 Bad Request` を返却し、エラーメッセージを表示 |
| **型チェック** | 文字列（`string`）であること | HTTP `400 Bad Request` を返却し、エラーメッセージを表示 |
| **最大文字数** | **1,000文字以内**（前後の空白除去後） | HTTP `400 Bad Request` を返却し、エラーメッセージを表示 |

### 3.4. エラーハンドリング要件

| エラー種別 | 想定ケース | HTTPステータス | 画面表示メッセージ（例） |
| --- | --- | --- | --- |
| **入力値不正** | 未入力、1,000文字超過 | `400` | 「質問内容を1文字以上1,000文字以内で入力してください。」 |
| **APIキー未設定** | サーバー側の環境変数不備 | `500` | 「現在AI機能を利用できません。管理者にお問い合わせください。」 |
| **外部API通信エラー** | Gemini API のタイムアウト、レート制限、ネットワーク障害 | `502` または `500` | 「AIからの回答取得に失敗しました。時間をおいて再度お試しください。」 |
| **予期せぬサーバーエラー** | その他の未捕捉例外 | `500` | 既存のグローバルエラーハンドラーへ `next(err)` で委譲 |

## 4. 非機能要件

### 4.1. アーキテクチャ・保守性

* 既存 TODO アプリ（`src/apps/todo/`）のディレクトリ構成および責務分離（Router / Controller / Service）を厳密に踏襲する。
* Gemini API 呼び出しロジックは `src/apps/ai/aiService.ts` に閉じ込め、Controller に外部 SDK の依存を持ち込まない。

### 4.2. セキュリティ

* `GEMINI_API_KEY` はサーバーサイドのみで使用し、フロントエンドの HTML / JS やエラーレスポンスに一切露出させない。
* AIからの回答をフロントエンドで描画する際は、XSS（クロスサイトスクリプティング）を防ぐため `textContent`（または適切なエスケープ処理）を使用する。

### 4.3. 性能・タイムアウト

* AI API 呼び出しのタイムアウト目安は **30秒** とし、応答遅延時にリクエストが無限に滞留しないようにする。

### 4.4. 既存機能への非干渉

* 既存のルーティング（`/`、`/todo` 等）、ミドルウェア、DB接続処理、404ハンドリング、グローバルエラーハンドリングに対して破壊的変更を行わない。

---

## 5. 対象外スコープ（本フェーズでは実装しないもの）

* 質問・回答履歴のデータベース保存機能
* チャット形式での文脈（会話履歴）保持機能
* ストリーミング形式（Server-Sent Events 等）での逐次テキスト描画
* ユーザー認証・権限管理の新規追加（既存アプリに認証ミドルウェアが存在する場合のみ、設計フェーズで適用要否を確認）
